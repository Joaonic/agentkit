# New ADR

## Create ADR When

- architecture boundaries/dependencies change
- contract/persistence/security strategy changes
- non-trivial tradeoffs affect multiple modules/teams

## Mandatory Sections

1. context
2. decision
3. alternatives considered
4. consequences (positive/negative)
5. rollout/migration notes
6. validation strategy

## Quality Bar

- decision is specific and testable
- alternatives are real and comparable
- consequences include operational impact
